# Maritime Atlas

**Морской атлас** - открытая картографическая система для трёх задач: плотность судоходства, грузопотоки и отслеживание судов по AIS.

## Возможности

| Слой | Показатель | Данные | Статус начальной поставки |
|---|---|---|---|
| Плотность судоходства | Судно-часы на пространственную ячейку, либо растр AIS | Собственные AIS-наблюдения; импорт GeoTIFF World Bank | Интерфейс и импорт готовы; реальные данные нужно загрузить |
| Грузопотоки | Тонны на направлении в год | GeoJSON морских коридоров + CSV с подтверждёнными объёмами | 15 схематичных коридоров; объёмы не заданы |
| Движение судов | Последняя AIS-позиция по MMSI | AISStream WebSocket | Подключается по бесплатному ключу; из коробки позиций нет |

**Ограничение:** схема маршрута не подтверждает его годовой тоннаж. Портовые суммарные объёмы IMF PortWatch нельзя автоматически приписывать отдельной паре портов. Статический GitHub Pages не может сам принимать AIS WebSocket и хранить ключ. Для живых позиций требуется локально запущенный приёмник либо отдельный сервер.

## Быстрый старт на macOS

```bash
cd ~/Downloads/maritime-atlas
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
maritime-atlas serve
```

Откройте **http://127.0.0.1:8020**. На карте сразу видны 15 демонстрационных морских коридоров с **неподтверждёнными тоннажами**. Два других слоя заполняются подключёнными данными. Установить растровый импорт можно отдельно:

```bash
python -m pip install -e '.[raster]'
```

## 1. Плотность судоходства

### Вариант A: исторический мировой растр World Bank / IMF

Скачайте Global Shipping Traffic Density: [World Bank](https://datacatalog.worldbank.org/search/dataset/0037580/global-shipping-traffic-density) или [архив Zenodo](https://zenodo.org/records/16894236). Распакуйте архив; используйте выбранный GeoTIFF в вашей локальной папке. **Не добавляйте большой исходный GeoTIFF в Git.**

```bash
maritime-atlas density-raster \
  --input '/ПУТЬ/К/ИСХОДНОМУ/РАСТРУ.tif' \
  --source-url 'https://datacatalog.worldbank.org/search/dataset/0037580/global-shipping-traffic-density' \
  --period '2015-2021'
```

Команда репроецирует растр в Web Mercator, уменьшает его для веб-карты и создаёт `docs/data/density.png` плюс `docs/data/density_meta.json`. Плотность World Bank основана на AIS-позициях, а не на массе грузов. Оригинальная лицензия набора - CC BY 4.0; сохраняйте атрибуцию при публикации. Срок наблюдений и метрику проверяйте по метаданным конкретного скачанного слоя.

### Вариант B: локальный AIS за выбранное время

После запуска AISStream сохраните наблюдения; затем:

```bash
maritime-atlas build-density --csv runtime/ais_observations.csv --cell-size 0.5
```

Результат - `docs/data/density.geojson`, где `ship_hours` означает число уникальных пар (MMSI, час UTC) внутри ячейки. Это плотность за период **вашего сбора**, не глобальная историческая статистика. `positions` отдельно показывает число полученных AIS-сообщений.

## 2. Грузопотоки

Шаблон `data/corridors.geojson` содержит 15 схематичных морских направлений с промежуточными точками. У них нет достоверного тоннажа по паре портов, поэтому линии отображаются пунктиром. Для расчёта толщины заполните `data/flow_observations.csv`:

```csv
route_id,year,cargo_tonnes,source_url,method
```

Для каждого направления указать **тонны груза**, дату, источник и метод. Нельзя подставлять национальные объёмы экспорта/импорта в отдельную портовую линию. В демо-таблице специально отсутствуют вымышленные значения.

```bash
maritime-atlas build-flows --year 2025
```

Создаётся `docs/data/flows.geojson`: линии с проверенными значениями становятся сплошными и масштабируются по тоннажу; прочие остаются пунктирными. Маршрутные точки **не пригодны для навигации**. Для фактической геометрии необходимо сопоставить OD-рейсы с историческими AIS-треками либо валидированной морской сеткой. Для корректной мировой агрегации по сегментам требуется полная OD-матрица с массой груза и маршрутом каждого рейса.

## 3. Позиции судов AISStream

Получите бесплатный API-ключ на [AISStream](https://aisstream.io/), затем:

```bash
cp .env.example .env
nano .env
```

Укажите `AISSTREAM_API_KEY=ВАШ_КЛЮЧ` и сохраните. В новом окне Terminal из папки репозитория с активированной `.venv`:

```bash
maritime-atlas track --bbox 49 -7 53 4 --minutes 30
```

`--bbox` задаёт границы в формате **юг запад север восток** в градусах. Пример - часть Ла-Манша и Северного моря. Приёмник записывает `runtime/vessels.geojson` и `runtime/ais_observations.csv`; локальная карта на `http://127.0.0.1:8020` проверяет новые позиции каждые 15 секунд. Нельзя ставить ключ в браузерный JavaScript или коммитить файл `.env`.

AISStream предоставляет прямой поток событий, **не гарантирует исторические данные, полноту мирового покрытия и непрерывность доступа**. В проекте поддерживается повторное подключение и сохранение последней полученной позиции за сессию. Отсутствие позиции не означает отсутствие судна.

## Jupyter Notebook

Откройте `notebooks/01_connect_from_github.ipynb` и задайте `GITHUB_USER`. При необходимости установите `requests` и `pandas` через `python -m pip install -e ".[notebook]"` из каталога проекта. Ноутбук загружает слои из вашего публичного GitHub-репозитория, показывает таблицу и встраивает опубликованную карту.

## Экспорт

В веб-карте доступны **GeoJSON**, **CSV** и **PNG** для активного слоя. GeoJSON сохраняет геометрию и атрибуты; CSV - табличные поля с сериализованной геометрией; PNG - снимок карты. При экспорте растра кнопка GeoJSON отдаёт только ячеистые векторные наблюдения, если они есть; растровый оригинал хранится отдельно как `density.png`.

## Структура

```text
maritime-atlas/
├── src/maritime_atlas/
│   ├── api.py                       # Локальный JSON API и раздача сайта
│   ├── cli.py                       # Команды запуска и экспорта
│   ├── providers/aisstream.py       # AISStream -> локальные наблюдения
│   └── processing/
│       ├── density.py               # AIS -> GeoJSON ячеек
│       ├── flows.py                 # Таблица тоннажей -> линии
│       └── raster.py                # GeoTIFF -> PNG Web Mercator
├── data/
│   ├── corridors.geojson            # 15 схематичных направлений
│   └── flow_observations.csv        # Шаблон массы груза
├── docs/
│   ├── index.html                   # Статический сайт для GitHub Pages
│   ├── app.js                       # MapLibre, интерактивные слои, выгрузка
│   ├── styles.css                   # Дизайн
│   └── data/                        # Публичные экспортированные слои
├── notebooks/01_connect_from_github.ipynb
├── tests/
├── runtime/                        # Локальный AIS, не попадает в Git
├── ARCHITECTURE.md
└── SETUP_MAC.md
```

Относительно [OSIRIS](https://github.com/simplifaisoul/osiris) сохранено разделение **источники → API/обработка → MapLibre-визуализация**. Вместо большого Next.js-приложения выбран компактный Python + JavaScript: меньше файлов, удобнее из Jupyter и подходит для GitHub Pages. Код OSIRIS сюда не копировался.

## Источники и методология

- [World Bank - Global Shipping Traffic Density](https://datacatalog.worldbank.org/search/dataset/0037580/global-shipping-traffic-density): открытые исторические плотности AIS, CC BY 4.0.
- [IMF PortWatch](https://portwatch.imf.org/): оценки активности портов и стратегических проливов; не готовая OD-матрица для всех линий.
- [AISStream documentation](https://aisstream.io/documentation): бесплатный поток сообщений AIS; регистрация и ключ обязательны.
- [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/): WebGL-картография.
- [OpenFreeMap](https://openfreemap.org/): базовая картографическая подложка и атрибуция OpenStreetMap.
- [GitHub Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site): публикация из папки `/docs`.

## SEO и индексация

В `docs/index.html` присутствуют `lang=ru`, `<title>`, `description`, Open Graph и Schema.org `WebApplication`; `robots.txt` разрешает индексацию. После публикации и получения настоящего URL добавьте в `<head>` canonical и `og:url`, например `https://USERNAME.github.io/maritime-atlas/`. Без известного адреса он намеренно не подставляется. Для репозитория заполните **Description** и **Topics** в GitHub; название репозитория не подменяет поисковую оптимизацию сайта.
